# 商品库存与秒杀系统设计文档

## 1. 系统概述

本系统是一个分布式商品库存与秒杀系统，采用微服务架构设计，主要考察分布式系统的核心能力：

- **服务拆分与治理**：用户服务、商品服务、库存服务、订单服务
- **分布式事务与一致性**：秒杀场景下的库存一致性保证
- **高并发处理**：Redis预减 + 分布式锁防止超卖
- **负载均衡**：Nginx轮询算法分发请求
- **容器化部署**：Docker + Docker Compose 编排
- **缓存策略**：Redis缓存 + 缓存穿透/击穿/雪崩处理

## 3. 服务拆分

### 3.1 用户服务 (user-service)
- **端口**: 8081/8082 (多实例)
- **功能**: 
  - 用户注册/登录
  - JWT认证
  - 会话管理
  - 用户信息管理
- **技术栈**: Spring Boot + JPA + Redis + JWT

### 3.2 商品服务 (product-service)
- **端口**: 8083
- **功能**:
  - 商品CRUD
  - 商品上下架
  - 商品详情查询
  - Redis缓存商品信息
- **技术栈**: Spring Boot + JPA + Redis

### 3.3 库存服务 (inventory-service)
- **端口**: 8084
- **功能**:
  - 库存管理
  - 秒杀库存扣减
  - 分布式锁（Redisson）
  - Redis预减库存
  - 库存同步（Redis → MySQL）
- **技术栈**: Spring Boot + JPA + Redis + Redisson

### 3.4 订单服务 (order-service)
- **端口**: 8085
- **功能**:
  - 订单创建
  - 订单查询
  - 订单状态管理
  - RabbitMQ异步处理
- **技术栈**: Spring Boot + JPA + RabbitMQ + Redis

### 3.5 API网关 (api-gateway)
- **端口**: 8080
- **功能**:
  - 路由转发
  - 认证鉴权
  - 限流降级
- **技术栈**: Spring Cloud Gateway + Redis + JWT

## 5. 秒杀核心设计

### 5.1 秒杀流程

```
用户请求秒杀
    ↓
Redis预减库存（原子操作）
    ↓
库存 < 0？ → 库存不足，返回
    ↓
加分布式锁（Redisson）
    ↓
双重检查库存
    ↓
库存 <= 0？ → 回滚Redis，返回库存不足
    ↓
创建订单（异步消息）
    ↓
减库存（MySQL）
    ↓
释放分布式锁
    ↓
返回秒杀成功
```

### 5.2 防止超卖的三层防护

#### 第一层：Redis预减库存
```java
// 原子操作，减少数据库压力
Long stock = redisTemplate.opsForValue().decrement("stock:" + productId);
if (stock < 0) {
    return "库存不足";
}
```

#### 第二层：分布式锁
```java
RLock lock = redisson.getLock("seckill:lock:" + productId);
lock.lock(10, TimeUnit.SECONDS);
try {
    // 秒杀逻辑
} finally {
    lock.unlock();
}
```

#### 第三层：数据库乐观锁
```java
@Version
private Integer version;

// 更新时检查版本
UPDATE inventory SET stock = stock - 1, version = version + 1 
WHERE product_id = #{productId} AND version = #{version}
```

### 5.3 缓存问题处理

#### 缓存穿透
- **问题**: 查询不存在的数据，每次都打到数据库
- **解决方案**: 
  - 缓存空值（设置较短过期时间）
  - 布隆过滤器

#### 缓存击穿
- **问题**: 热点数据过期，大量请求同时打到数据库
- **解决方案**:
  - 互斥锁：只有一个线程重建缓存
  - 永不过期 + 异步刷新

#### 缓存雪崩
- **问题**: 大量缓存同时过期
- **解决方案**:
  - 随机过期时间
  - 多级缓存（本地缓存 + Redis）

### 7.2 Nginx配置

#### 负载均衡算法
- **轮询**（默认）: 每个请求按时间顺序分配
- **hash**: 同一IP的请求分配到同一服务器
- **ip_hash**: 基于IP哈希
- **least_conn**: 最少连接优先

#### 动静分离
- `/static/` → 静态资源
- `/api/` → 反向代理到后端服务
